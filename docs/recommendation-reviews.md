# 每期推荐与复盘

实现参考同机 `lottery-k8` 的实际推荐留档与原票组复盘流程，适配本项目的双色球模型、7 个现有预设、文件存储和冻结审计协议。新增少注覆盖 v1；原冻结确认窗、模型权重拟合范围和原 7 个预设的出票规则保持原样。

## 使用

分档号码池入口为 `/pools`（代理部署时 `/ssq/pools`），首页与复盘页均可进入。主要观察全部 6 红入池的期数比例与漏号，蓝球覆盖作为辅助。

启动原有 `serve` 命令后，打开 `/reviews`。反向代理在 `/ssq/` 下时，打开 `/ssq/reviews`。首页导航和生成结果中的“查看本次推荐留档”均可进入。页面有期号、来源、方案三级选择，并提供全号码轨迹、专家权重、候选漏斗、覆盖与重复统计、完整展开票组的逐注对奖。

- “留档下一期”用当前历史一次性保存原 7 个预设和少注覆盖 v1 的 9 个方案，共 16 个实际票组。已有每期档案保留首次文件，不覆盖重算。数据不够新、错过截止、计算或写盘越过截止时拒绝创建。
- 首页生成或保存的个人方案独立留档，相同历史、源码、期号和方案去重。保存页面显示的方案时会核对档案摘要，数据、目标期或参数变更后须重新生成，避免把另一组号码静默记成刚才的票面。
- “同步开奖并复盘”先从 500.com 更新数据，再按实际推荐复盘。“核对本地开奖”使用已有 CSV；不会从网络下载。
- 每期档案可比较当时保存的全部方案，并按方案范围与相同预算筛选；个人方案与旧版保存记录在来源中单独选择。旧记录只使用当时保存的票面，评分与原因标为未留存。
- 待开奖时，号码命中、逐注中奖、奖金与漏斗命中均为 `null`，页面显示 `—`。历史缺档保持缺档，不使用当前模型生成历史推荐。输入已包含目标期开奖的个人档案明确提示事后生成。

自动运行继续使用已有命令：

```bash
target/release/ssq cycle --data data/ssq.csv --audit audit/log.jsonl --out publish --review-dir reviews
```

外部定时任务需要周期性执行此命令，例如每 30 分钟一次。`serve` 本身不启动后台定时任务。本地周期按周二、周四、周日的常规开奖日、北京时间 21:10 截止推算；休市、节假日与跨年期号应人工核对公告。每期新档案对跨年和非紧邻目标保守拒绝。

## 留档与复盘

以 `--out publish` 为例，新功能目录是：

```text
recommendations/
  daily/26116.json                  # 每期全部预设的实际票组和证据
  interactive/26116/<sha256>.json    # 生成或保存的个人方案
  reviews/26116/daily.json          # 绑定每期推荐摘要和开奖摘要的复盘
  reviews/26116/<sha256>.json        # 个人方案复盘
```

档案包含数据截止期、历史前缀摘要与期数、协议摘要、相关源码摘要、软件环境、完整单注票组和每个号码的模型证据。采用完整 JSON 的 SHA-256 校验，临时文件写盘后原子创建，不覆盖已有文件。浮点评分启用 JSON 精确往返解析，保证读写后的摘要一致。

复盘读取原档案中的票组与证据，不重新运行当前模型恢复推荐。复盘绑定推荐摘要与目标期开奖结果摘要。历史前缀变化、档案摘要错误、已复盘开奖发生变化时拒绝计算或覆盖，并返回错误。批量核对会继续处理其他有效档案。复盘是首次成功核对时保存的完整结果，重复核对保留原字节；GET 接口可预览尚未保存的复盘，不写盘。

每份档案的时间来自本机时钟，日历也不是官方已核验赛程。这些是运营留档，不加入冻结确认窗的显著性检验。**本地哈希不能独立证明开奖前已公开**；本实现没有接入独立可信时间戳，界面与导出均明确标注。

## 统计与奖项

复式和胆拖先完整展开成 6 红 + 1 蓝单注。号码曝光次数及重复位置包含实际重复投注；完全重复的票另外计数。红球并集覆盖与单注命中、中奖注数分别计算。均匀基准的红球覆盖命中期望为 `并集大小 × 6 / 33`，模型评分是排序依据，不是中奖概率。

常规一至六等奖按单注命中红球数与蓝球核对。固定奖金只累加三至六等奖；一、二等奖金额需核对当期公告，未估算收益率或净利润。

依据[官方双色球规则](https://www.scflcp.com.cn/yxgz/823145252.jhtml)，2026014 期起规则新增在特定奖池条件下执行的特别规定；3 红 0 蓝的福运奖取决于当期是否执行特别规定。当前 CSV 没有奖池和特别规定状态，因此此类票只标记“福运奖待核实”，不计入已确认中奖注数或固定奖金。派奖、税费也不计入。

| POST | `/api/recommendations/freeze` | 按本地周期门槛留档下一期全部预设与模型号码池 |
| GET | `/api/pools` | 六档号码预览及独立的历史因果回放 |
| GET | `/api/pools/observations` | 按实际每日留档统计六档覆盖，待开奖与缺档不计入比例 |

## 少注覆盖 v1

参考 `lottery-k8/src/efficiency.py` 的固定结构目标，新建的每期档案追加 9 个方案，保存版本、固定种子、完整票组及所用依据。已存在的每日档案继续保留首次版本与原方案数量，不补算历史推荐，不追加新策略。原 7 个预设的算法和预算不变。

| 档案策略 | 注数 / 成本 | 目标 |
| --- | --- | --- |
| `efficiency:compact` | 依原号码并集确定 | 分别保留冻结票组的红球并集、蓝球并集，用最少单注数重组 |
| `efficiency:model:2`～`:5` | 2～5 注 / 4～10 元 | 按开奖前融合排名，红球不重复覆盖 12～30 码，配前 2 个蓝球 |
| `efficiency:uniform:2`～`:5` | 同上 | 按期与颜色分离的固定种子打乱号码，提供相同预算和覆盖结构的均匀分散对照 |

融合排名方案保留当时评分与权重；均匀对照明确标为结构方案，不填写模型评分、提名专家或融合权重。没有使用历史命中搜索种子、预算或冠军方案。这些方案改善结构效率，不构成已验证的选号优势，也不进入原确认窗的预注册检验。

### 同覆盖减注试算

选择已有实际推荐时，接口额外返回 `compact_preview`，页面单独展示“同覆盖减注 · 结构试算”。只有能减少注数时才提供试算；复式和胆拖按原完整单注票组处理。试算达到注数下界：

```text
max(ceil(红球并集大小 / 6), 蓝球并集大小)
```

双色球每注只能覆盖 6 个不同红球和 1 个蓝球，因此需要同时满足两个下界。蛇形分组和必要的确定性补位可以达到这个注数。分别保留红球和蓝球并集，会保留覆盖到的不同开奖号集合，但不会保留原红蓝配对、号码曝光、单注命中、中奖注数或奖金。

试算只使用所选档案保存的票组和当前该期开奖号码，不重新运行模型恢复旧依据。它带有 `actual_recommendation: false` 及待开奖/事后结构试算类型，支持单独导出；不写入原推荐、已保存复盘或实际方案列表。历史缺档不产生试算。未来每日留档中的 `efficiency:compact` 则是在截止前真实冻结的独立方案，按其原始票组复盘。

### 比较指标

方案卡片可按相同预算筛选。详情同时报告每元红球覆盖、覆盖超额、每注平均红球命中、命中蓝球的注数、每注都出现的红球、漏中红球的筛选原因，以及原有覆盖、重复、奖项统计。

- 每元红球覆盖 = 不同红球数 / 完整票组成本；不是奖金或收益率。
- 红球覆盖超额 = 并集命中数 − 红球并集大小 × 6 / 33。
- 蓝球并集覆盖基准 = 不同蓝球数 / 16。
- 每注红球命中均匀基准 = 36 / 33；蓝球命中注数期望 = 注数 / 16。

待开奖的命中、超额、命中分布及漏中原因均为 `null`。不同预算的覆盖或单期奖金不能直接用于判断预测优势。已保存的旧复盘只在读取响应中从其原票面和原命中字段补充结构指标；不重新计奖，不覆盖旧文件。原始 JSON 下载继续返回首次保存的字节。

验证命令：`cargo test --release --all-targets`。覆盖池测试穷举全部合法红球/蓝球并集大小，核对注数下界、号码有效性、两个并集和无重复整注；另验证相同预算对照、无模型评分的均匀方案、待开奖空值、旧版档案/复盘字节保留，以及结构试算的覆盖相同但逐注奖项可变。

## 小号码池筛选 v1

按 8／10／12 个红球 × 1／2／3 个蓝球固定比较，共 9 种规格。每期首次自动留档会在 `number_pools` 中保存协议加权融合的 9 个小池、全部红蓝球排名、评分及冻结权重，独立于原单注票组。复盘读取原池核对命中和漏号，不按最新模型重选号；待开奖为 `null`。旧档案缺少小池时继续显示缺档，不从旧评分补造实际推荐。

小池中的全部开奖号即使齐全，也不表示某一张单注中奖。本功能不自动把小池展开成复式，不按注数、每元号码覆盖或奖金作为主要筛选目标。

`GET /api/pools` 提供只读的因果回放报告。9 种红球排序包括协议加权融合、等权融合和原 7 个专家；均使用同一份冻结蓝球排序，按相同池大小比较红球筛选能力。展示全部方法，不从已查看的历史窗口中挑冠军。确认窗之前的融合权重只用更早的样本外结果展开拟合，25111 期起冻结；每期专家状态只使用该期以前的开奖。

主要指标是 **6 红与蓝球同时全部入池的期数 / 真实开奖期数**；同时展示全 6 红、至少 5 红、平均中红、平均漏红、红球召回与所选号码精确率。均匀基准为：

```text
红球平均命中 = 6 × 红球池大小 / 33
红球全包率 = C(红球池大小, 6) / C(33, 6)
6红1蓝全包率 = 红球全包率 × 蓝球池大小 / 16
```

新增指标仍为探索性复盘，不加入原 25 项预注册检验，也不自动修改原融合权重。最近 30／60 期互相重叠；Wilson 区间未处理多重比较和时间相关，不能当作下一期覆盖承诺。全包次数同为 0 时不据此自动选择更小池或声称冠军。

页面可导出明确标记未发布的研究池。点击留档时核对显示时的数据摘要和目标期；输入或目标已变化则要求刷新，避免静默保存另一份号码。原始每日档案与已保存复盘保持不可覆盖。以前加入的分散票组、同覆盖减注保留在辅助区域，不作为小池筛选能力提升的证据。

复现：

```sh
cargo run --release -- pool-review --data data/ssq.csv --out small-pool.txt --json small-pool.json
cargo test --release --all-targets
```

截至 26117 的本次复盘见 `small-pool-review-2026-10-14.txt`，全部方法、窗口、输入与研究源码摘要见同名 JSON。开奖核对来源为上海福彩官网 https://www.swlc.net.cn/index.html ，规则来源为 https://www.scflcp.com.cn/yxgz/823145252.jhtml 。

## 红球数量比较 v2

按用户“先比较 14–24 个红球的实际全包率，再定数量”的要求，主指标改为 **全部 6 个开奖红球入池的期数 / 真实开奖期数**。这里按真实开奖进行因果回放，不能冒充当时实际发布的推荐记录。蓝球 1–3 个与 6 红 1 蓝同时全包作为辅助，不影响红球数量曲线。

`GET /api/pools` 的报告版本为 2，`red_sizes` 为完整的 6–33，默认关注范围 `focus_red_range` 为 `[14,24]`。各观察窗新增 `red_curves`（9 种排序 × 28 种大小），提供全 6 红次数、比例、描述性 Wilson 区间、同大小均匀基准及差值、平均漏红和各蓝球规格的辅助命中。`additional_full_red_periods` 是增加当前第 R 个红球相对 R−1 红新增的全包期数，6 红时为 `null`。

`red_frontiers` 保留 14–24 范围内全包期数首次达到各水平时的最小红球数，省略全包次数没有增加的规格。这只说明当前窗口中哪些增号没有增加全包次数；不据此调整未来模型或自动选择下一期数量。页面也允许切换其他数量范围与排序，手动预览及导出始终标记 `actual_recommendation:false`。

留档规格继续使用 **v1 的 8／10／12 红 × 1／2／3 蓝**。报告中的 `archive_version:1`、`archived_red_sizes:[8,10,12]` 和 `next.weighted_pools` 均明确这一点；原 `cells` 81 行仍保留，供已有读取方使用。14–24 红目前仅比较，不自动启用新的未来留档规格，历史档案不补写。

截止 26117，协议加权融合在 156 期确认窗中，14 红全包 3 期，18 红 7 期，20 红 9 期，24 红 16 期；16／17 红同为 5 期，18／19 红同为 7 期。全部 3334 期回放中，24 红全包 407 期（12.21%），同大小均匀基准为 12.15%。数量增大提高了全包率，当前证据没有确认稳定的筛选优势。这些新增指标未进入原预注册检验。

本次完整结果保存为 `red-pool-size-review-2026-10-14.txt` 与同名 JSON，原 v1 报告保持原快照。复现：

```sh
cargo run --release -- pool-review --data data/ssq.csv --out red-pool-size-review.txt --json red-pool-size-review.json
cargo test --release --all-targets
```

## 六档模型号码池观察

用户进一步要求提供不同档位的模型号码池，启用 **14／16／18／20／22／24 红六档**，分别标记 A–F。档位只表示数量，不表示模型置信度。所有档位共用协议冻结加权融合排序，较大池逐层包含较小池，每增加一档多选两个红球；蓝球共用冻结排序，分别保存 1／2／3 蓝。

新号码池档案版本为 2，包含六档 × 三种蓝球规格共 18 个观察池，以及原有 8／10／12 红 × 1／2／3 蓝的 9 个对照池，总计 27 个。每个池保存 `group`（`observation` 或 `legacy`）及 `tier_id`。版本 1 的原九池档案继续可读，首次留档已存在时不会追加新池或修改字节。留档与复盘仍由原 `cycle` 和网页封存、核对流程处理。

`/pools` 首屏列出六档具体号码与逐层新增号码，可以选择蓝球数量并导出六档预览。预览标记 `actual_recommendation:false`，成功封存后才计入实际观察。每日复盘页面默认显示六档、两蓝，可切换蓝球数和原小池；开奖后标记命中、漏号和 `smallest_full_red_tier`（本期六档中最少多少红球已包含全部六红，没有全包档或待开奖时为空）。

新增只读接口 `GET /api/pools/observations` 只扫描实际每日档案，核对摘要和数据前缀，再用原始号码对本地开奖计分。每格的 `n` 是该规格已保存且已开奖的期数；`pending` 单列待开奖数，`n=0` 时覆盖率和平均漏红为 `null`。未保存观察档的旧期只增加 `missing_tier_archives`，不会恢复成实际推荐；无效档案及晚于常规开奖时间保存的档案排除并返回 `errors`。统计读取不会写入复盘或修改档案，不依赖当前模型重新选号。

研究报告版本增至 3，档案版本为 2；全部历史回放继续独立保留，旧报告快照不覆盖。六档用于前瞻观察，不按已有历史窗口自动选择冠军或修改冻结权重。本地留档仍无独立时间戳证明。


## 与 lottery-k8 一致的前端流程

首页使用同一顺序的七个页签：方案生成、我的方案与对奖、每期推荐与复盘、开奖历史、科学回测与优化、研究评估、系统设置。复盘和研究在首页内打开，仍可独立访问 `/reviews`、`/research` 与 `/pools`。支持 `/ssq/` 代理前缀及期号、来源的直接链接，本地固定版本 Vue 随服务提供。

预设会填入参数并生成；自定义参数点击生成才运行。打开首页或同步开奖不自动生成推荐，不会因此新增实际档案。生成真实票组仍使用原接口留档；保存到方案库与复制文本均读取生成时的期号、参数和号码，后续编辑表单不改变已经显示的方案。输入摘要变化时旧预览禁止保存。六档号码池在生成页可选档位与1–3蓝，封存时保存原有完整六档；未到可封存窗口时只显示预览。

每期复盘顶部先选择期号与来源，默认展示全部实际策略及各档号码池。每张卡列出原始红蓝号码并标记本期开奖命中，点击“查看完整票组”定位逐注核对；仍可按方案范围或相同预算筛选，导出完整49球明细。历史缺档保持缺档，待开奖不标记命中。

“我的方案与对奖”只显示实际保存记录。历史重算移至研究页，`GET /api/history` 增加可选的五位期号 `from`、`to`，摘要覆盖整个选定窗口，`before` 与 `limit` 只分页。空窗口均值为空，导出明确标记 `actual_recommendation:false`。冻结模型、票面规则与旧档案没有因界面调整而重算。

## 三模型前瞻对照与漏号诊断（号码池版本 3）

此前的版本 2 档案保留加权模型 27 个号码池。版本 3 只用于后续首次冻结的新期：保留原 27 个池，并新增等权融合和均匀红球对照各 18 个六档池，共 63 个池。原有 16 个实际票组、生产融合权重和出票规则不变。已存在的每日档案保持首次字节，26118 期不追加新模型。

三模型均比较 14／16／18／20／22／24 红与 1–3 蓝，蓝球统一使用原加权排名，只比较红球筛选差异。等权模型保存七专家的等权评分、权重和完整排名；均匀模型使用固定协议种子与目标期号，通过独立的 `ssq-pool-comparison-v1` 随机流生成完整红球排名，不使用历史命中来挑种子。所有模型的池须与其原始排名前缀、共享蓝球排名一致，完整保存各规格。对照模型为观察用途，不根据近期胜率自动替换主模型。

`number_pools.pools` 继续表示原加权模型的 27 个池；新增 `comparison_models` 保存两个对照及其各 18 个池，`comparison_policy` 保存固定规则。冻结响应中的 `number_pools` 保持原含义；`comparison_number_pools` 为新增的 36 个池，`comparison_models` 为包含主模型的总模型数 3。旧版可能只有一个模型或没有六档，接口如实返回。

`GET /api/pools/observations` 的 `cells` 保留加权模型统计，新增 `comparison_cells` 为各模型的独立累计，`paired_cells` 为三模型均提前留档的共同期次。正式模型比较使用 `paired_cells`：同一期、同红球数、同蓝球数、同一个已开奖分母；待开奖单独计数，缺少对照的旧期列为排除期次，不算失败。展示全6红率、平均漏红、至少5红次数及描述性 Wilson 区间。区间未作多重比较校正，不直接宣布优胜模型；规则变更应新建版本，并用之后未参与调参的开奖检验。

逐期复盘从原始完整排名计算六个开奖红球的名次、漏号名次、开奖蓝球名次，以及 `diagnostics.minimum_full_red_prefix`。这个值为六个开奖红球名次的最大值，可能是 17、19 等未作为观察档位保存的数量；字段 `is_recommended_pool:false` 明确它属于开奖后诊断。实际成功档位仍由原先保存的六档池计算，不能把事后最小前缀当作当时的推荐。待开奖或未保存排名时诊断为空。

读取旧档案时可以从其原排名派生诊断，响应中增加字段，不改写原推荐或已保存复盘，也不恢复旧期未保存的等权、均匀模型。原始 JSON 下载仍返回首次字节。复盘页仅允许选择该期真正保存的模型；研究观察页可切换三套当前预览，并单列共同期次统计。研究预览导出继续标记 `actual_recommendation:false`。

方案对照区优先展示已经留档的同覆盖最少注票组与原冻结票组的注数、成本和集中押号情况。它保留红蓝球各自并集，但单注组合和对奖结果可能改变；未发布的结构试算仍明确标记，不将其当作已留档方案。

## 覆盖复盘与均衡组票 v1（2026-10-16）

新预设 `balanced14` 取原融合排名前14红与前2蓝，生成8注16元。新增 `balanced` 模式支持12–24红、2–20注、1–3蓝，红球总位置不得小于池大小。组票完整使用所选号码池，每个红球的总曝光限制在总红球位置除以池大小的向下、向上取整之间，且红球组合不重复。14红8注时每号出现3–4次；这只优化组票覆盖，不修改原融合权重或保证单注包含全部开奖号。方案留档额外保存 `coverage_optimization` 的版本、所用数量及组票目标。

首次冻结的新期保存原16个策略及新均衡方案，共17个。已经冻结的26118、26119期保持原始文件和16个策略，不为展示改进而追加；用户主动生成的新方案单独记为交互档案。63个号码池和三模型共同期次对照规则保持不变。

`GET /api/coverage` 提供独立的探索性因果回放，`actual_recommendation:false`。同原12码池、同融合前14码池的组票对照分别报告，以免把扩大池的效果误当作排序能力提升。报告同时列出固定公式的均衡排名试验；截至26118，该试验在近60期14/18红的表现较差，未加入自动冻结或生成预设。研究区域保留失败结果和固定决策截止期，不自动挑冠军。蓝球扩大范围和均匀覆盖另有基准，不以单期漏蓝为由扩大数量。

均衡票组的模板只依赖池大小与注数，按固定目标生成并缓存，再映射到当期原融合排名；缓存不包含开奖或模型评分。原推荐和复盘文件不改写，研究导出、已留档票组及未来验证继续分别标记。

## 原档红蓝覆盖归因（2026-10-28）

`GET /api/pools/observations` 的 `compression_cells[].joint_coverage` 追加四个互斥结果：`full_draw`（红蓝全入池）、`red_miss_only`（仅红球未全入池）、`blue_miss_only`（仅蓝球未入池）、`both_miss`（红蓝都漏）。每类保存 `periods`、`issues`、`rate`，四类相加等于该单元的 `n`；分母只包含同一期、同模型、同蓝球数量的小档与24红参照都已原始保存且已开奖的期次。待开奖计入 `pending`，缺少成对原池计入 `excluded_missing_pair`；没有已开奖样本时四类比例均为 `null`。

生成页与研究观察页展示归因与期号；均匀模型没有历史回放时仍可查看原档归因。分类使用原档号码核对，不重排旧期、不回写推荐或复盘。不同模型的可用样本可能不同，这里的次数不用于直接评选模型；“只漏蓝球”不能靠增加红球或更换红球模型补回。

## 蓝球命中目标与相同预算对照（2026-10-28）

`GET /api/blue` 返回原加权、等权及 `blue_hit_frozen` 的1–8蓝因果回放，`same_budget_tickets` 固定原加权16红、相同8组红球、8注16元，比较2／3／4蓝的覆盖期数、命中蓝球的注数及至少4红且蓝球命中的注数。`actual` 只配对原档中 `bluefocus2`、`bluehit2`、`bluefocus4`、`bluehit4` 四组票面；缺档不补造，待开奖不计入比例。`paired_reference_preset` 区分2蓝试验对原2蓝、4蓝试验对原4蓝。

生成接口可带 `expected_data_sha256` 绑定预览输入，输入变化时在生成与写档前拒绝；蓝球入口自动携带该摘要并绑定显示期号。`blue_model` 支持默认 `weighted` 和试验 `blue_hit_frozen`。试验参数、完整蓝榜和训练证据保存为 `blue_ranking`，保存和复盘使用原票面。旧命名预设、协议冻结票组拒绝换蓝榜；试验只支持当前开奖紧邻下一期。均衡组票蓝球数量为1–8且不多于注数；原号码池1–3蓝及原预设预算不变。后续首次每日留档25策略，已有26124保持21策略、171个号码池，四组新策略不追补到旧档。

## 16红以内独立观察（2026-10-28）

每日档案可带 `small_red_pools` v1扩展，保存原加权与 `small_recent` 两模型的12／14／15／16红，共8个仅红球池；独立于原171个红蓝规格池。保存原评分、近期指数评分、重号评分、固定融合规则和完整排名，按原输入历史核验。旧期没有扩展就保持缺档，已存复盘在GET时可只读补充新扩展诊断，原文件不重写。

`GET /api/small-red` 区分历史回放、下一期未封存预览及 `actual` 配对实际统计；只有扩展完整且两模型同数量都已保存的期次进入共同分母。待开奖与缺档不记失败，空样本覆盖率为null。已有26124未保存此扩展，不能把当前预览当作旧每日推荐。

`ranking_model:"small_recent"` 可用于个人单式／均衡方案，红球候选池不超过16；原冻结协议拒绝替换排名。首页生成使用所见红球池、8注16元和原榜2蓝，绑定预览期号与输入摘要。个人方案在独立来源中复盘，不混入每日小池实绩。
